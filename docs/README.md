# 📚 Mock:ctl Documentation

Welcome to the official documentation for **Mock:ctl**.

This directory contains the **Project Knowledge System (PKS)**, the single source of truth for the entire project.

The PKS documents every major product decision, engineering decision, architectural guideline, AI workflow, and development standard used throughout the lifecycle of Mock:ctl.

Documentation is considered a core part of the project and should evolve alongside the implementation.

---

# 🎯 Purpose

The documentation exists to:

- Define the product vision.
- Capture engineering decisions.
- Standardize development practices.
- Support AI-assisted development.
- Preserve project knowledge.
- Improve long-term maintainability.
- Reduce ambiguity.
- Provide onboarding for future contributors.

---

# 🧠 What is the Project Knowledge System (PKS)?

The **Project Knowledge System (PKS)** is a structured documentation framework that organizes every important aspect of the project into a collection of interconnected documents.

Rather than treating documentation as isolated Markdown files, the PKS treats every document as part of a single engineering knowledge system.

The PKS serves as the authoritative reference for:

- Product
- Engineering
- Architecture
- AI Workflows
- Development Standards
- Project Governance

# 📖 Documentation Categories

## 00-foundation

Foundation documents define the standards and rules that govern the entire project.

Examples include:

- Repository Blueprint
- Documentation Philosophy
- Documentation Style Guide
- Project Knowledge System
- Documentation Index

---

## 01-product

Product documentation defines **what** Mock:ctl is, **why** it exists, and **what** will be built.

Examples include:

- Vision
- User Personas
- User Journey
- Functional Requirements
- Product Requirements Document (PRD)
- Product Roadmap

---

## 02-engineering

Engineering documentation defines **how** the product will be built.

Examples include:

- Software Design Document (SDD)
- System Architecture
- Database Design
- API Design
- Coding Standards
- Testing Strategy

---

## 03-ai

AI documentation defines the workflows, prompts, and standards used for AI-assisted software development.

Examples include:

- Prompt Engineering Guide
- Prompt Library
- AI Coding Rules
- AI Review Checklist

---

## adr

Architecture Decision Records (ADRs) preserve significant technical decisions made during the project.

Each ADR explains:

- What was decided
- Why it was decided
- Alternatives considered
- Consequences

---

## diagrams

Contains Mermaid diagrams and other technical diagrams referenced by project documentation.

---

## assets

Contains static assets used throughout the documentation.

Examples include:

- Images
- Icons
- Illustrations

# 📏 Documentation Rules

Every official document should:

- Follow the Documentation Style Guide.
- Have a clearly defined purpose.
- Avoid duplicate information.
- Reference related documents.
- Remain synchronized with implementation.
- Be maintained throughout the project lifecycle.

# 🤖 AI-Assisted Development

Mock:ctl is designed to embrace AI-assisted software engineering.

AI coding agents should consult the Project Knowledge System before generating implementation.

The documentation provides the architectural context, engineering constraints, coding standards, and product requirements necessary for producing consistent, high-quality code.

# 🌱 Maintaining the PKS

The Project Knowledge System is a living documentation system.

Whenever the project evolves:

- Update the relevant documentation.
- Record important architectural decisions.
- Keep cross-references accurate.
- Preserve version history.
- Maintain consistency across all documents.

Documentation should never become outdated.
